*[blind 퍼징]: 피드백 없이 무작위로 입력을 던지는 방식. 깊은 버그엔 도달 못 함
*[코퍼스]: 퍼저가 보존하는 흥미로운 입력들의 모음
*[크래시 오라클]: 예외·패닉이 나면 버그로 보는 오라클. 조용한 논리 버그는 놓침
*[차분 오라클]: 두 구현의 답을 비교해 다르면 버그로 보는 오라클
*[속성 기반 테스팅]: 구체적 입출력 대신 모든 입력에 참일 성질을 검사하는 방식
*[워드리스트]: 경로·파라미터·계정명 후보를 모은 단어 목록. web2 퍼징의 생성기
*[ffuf]: web2 경로·파라미터 퍼징 도구. FUZZ 자리에 워드리스트를 끼워 요청
*[soft-404]: 없는 경로인데도 200을 돌려주는 서버 동작. 상태코드 오라클을 무력화
*[타이밍 오라클]: 응답 내용이 같아도 응답 시간 차이로 존재를 판정하는 오라클
*[레이트리밋]: 서버가 시간당 요청 수를 제한하는 것. 초과 시 429 반환
*[OpenAPI]: API의 경로·메서드·파라미터·응답 형태를 기술하는 스키마 표준
*[Swagger]: OpenAPI의 옛 이름
*[Schemathesis]: OpenAPI 스키마로 테스트를 자동 생성해 계약 위반을 찾는 도구
*[API 링크]: 한 응답의 값을 다음 요청 입력으로 잇는 OpenAPI 선언
*[상태저장 시퀀스]: 앞 응답이 뒤 요청을 결정하는 요청 나열. 호출 순서가 곧 입력
*[BOLA]: 한 사용자 자격으로 남의 자원에 접근·변경하는 인가 결함(OWASP API 1위)
*[스마트컨트랙트]: 블록체인 위에서 실행되는 프로그램. 상태가 영구 누적됨
*[Foundry]: Solidity 컨트랙트 개발·테스트 도구 모음 (forge/anvil/cast)
*[stateless fuzz]: 깨끗한 상태에서 함수를 한둘만 부르는 퍼징. 상태·순서 버그를 놓침
*[invariant 테스트]: 함수들을 무작위로 엮으며 상태를 누적하고 불변식을 검사하는 퍼징
*[핸들러]: invariant 퍼징에서 유효 호출자·의미 있는 인자를 주는 중간 컨트랙트
*[revert]: 컨트랙트 실행이 require를 못 맞춰 되돌려지는 것. 높으면 탐색 낭비 신호
*[shrink]: 불변식을 깬 시퀀스를 여전히 깨는 최소 호출로 줄여 보여주는 것
*[ghost 변수]: 불변식 검사를 위해 핸들러가 따로 추적하는 값(예: 지분 합)
*[커버리지 가이드 퍼징]: 코드 커버리지를 피드백으로 삼아 탐색을 편향시키는 방식
*[계측]: 프로그램이 어느 코드를 실행했는지 기록하도록 심는 장치
*[경계값]: 0·-1·최대값처럼 버그가 자주 숨는 극단 입력
