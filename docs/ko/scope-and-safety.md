# 범위와 안전

이 문서는 나머지 모든 장의 전제입니다. 랩을 시작하기 전에 읽으십시오.

## 대상은 항상 본인의 로컬 인스턴스입니다

이 교재의 모든 실습 대상은 독자가 자기 머신에서 `docker compose` 로 직접 띄우는
컨테이너입니다. 교재 어디에도 실제 서비스의 URL, 공개된 테스트 사이트,
메인넷에 배포된 컨트랙트 주소는 등장하지 않습니다.

이유는 단순합니다.

**허가 없이 남의 시스템을 퍼징하는 것은 대부분의 국가에서 범죄입니다.**
한국에서는 정보통신망법 위반에 해당할 수 있습니다. 퍼징은 그 성격상
대량의 비정상 요청을 보내므로, 스캐닝을 넘어 업무방해로 다뤄질 소지도 있습니다.
"취약점을 알려주려고 했다"는 동기는 법적 면책 사유가 되지 않습니다.

## 실무에서의 범위(scope)

감사 업무에서 퍼징을 쓸 때 계약서에 명시되어야 하는 것들입니다.

| 항목 | 왜 필요한가 |
|------|-------------|
| 대상 호스트·도메인·컨트랙트 주소 목록 | 와일드카드 범위는 서드파티 자산을 삼키기 쉽다 |
| 제외 대상 | 결제·메일 발송·SMS 등 부수효과가 외부로 나가는 경로 |
| 허용 시간대 | 퍼징은 부하를 만든다 |
| 요청률 상한 | 상한 없는 퍼징은 사실상 부하 테스트다 |
| 긴급 연락 체계 | 장애를 냈을 때 즉시 멈추고 알릴 상대 |
| 데이터 취급 | 퍼징 중 실제 고객 데이터가 응답에 섞여 나올 때의 처리 |

버그바운티 프로그램에 참여하는 경우, 프로그램 정책이 자동화 스캐닝과
퍼징을 명시적으로 허용하는지 먼저 확인하십시오. 다수가 금지하거나
요청률을 제한합니다.

## 부수효과 있는 엔드포인트

퍼징은 "어떤 입력이 들어갈지 모른다"는 전제 위에서 동작합니다.
그래서 다음 경로는 격리된 환경이 아니면 절대 대상에 넣지 않습니다.

- 메일·SMS·푸시 발송
- 결제·정산·출금
- 외부 웹훅 호출
- 계정 삭제, 데이터 파기
- 관리자 권한 변경

web3 에서는 여기에 하나가 더 붙습니다. **테스트넷이라도 남이 배포한 컨트랙트에
상태 변경 트랜잭션을 날리지 마십시오.** 이 교재의 web3 랩은 전부
로컬 `anvil` 체인 위에서 돌아갑니다.

## 랩 환경 격리

랩 컨테이너는 의도적으로 취약하게 만들어져 있습니다.
인터넷에 노출하지 마십시오.

- 포트는 `127.0.0.1` 에만 바인딩합니다 (compose 파일에 그렇게 되어 있습니다)
- 공용 Wi-Fi 에서 실습 중이라면 방화벽을 확인하십시오
- 실습이 끝나면 `docker compose down` 으로 내립니다
- 랩 컨테이너를 운영 네트워크와 같은 Docker 네트워크에 붙이지 마십시오

## 이 교재의 취약점 공개 태도

Part 1 의 타겟은 교육 목적으로 제가 직접 만든 것이고,
Part 2·3 의 타겟은 공개된 교육용 취약 애플리케이션입니다.
어느 쪽도 실제 제품의 미공개 취약점을 다루지 않습니다.

실무 감사 중 발견한 취약점은 이 교재에 등장하지 않습니다.
