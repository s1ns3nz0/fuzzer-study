# 5. ffuf — 워드리스트가 곧 생성기

**Part 1 · web2 감사**

4장에서 웹의 입력공간을 그렸습니다. 경로, 파라미터, 헤더, 상태.
그리고 링크로 도달 가능한 표면 아래에, 아무도 링크하지 않는 경로들이
숨어 있다는 걸 봤습니다. 크롤러는 그걸 못 찾습니다. 링크가 없으니까요.

닿는 방법은 하나뿐입니다. **추측해서 던지는 것.** 그게 이 장입니다.

## 이 장에서 답할 질문

- 숨은 경로를 어떻게 "생성"하는가
- 왜 워드리스트의 품질이 곧 탐색의 한계인가
- ffuf 의 매처(matcher)와 필터(filter)는 무엇이 다른가
- 파일명과 확장자처럼 축이 둘일 때 어떻게 조합하는가

## 5요소 위치

이 장이 다루는 요소: **생성**

| 요소 | 이 장에서의 형태 |
|------|------------------|
| 생성 | **워드리스트의 각 줄을 경로 후보로 던진다 — 이 장의 전부** |
| 변이 | 없음 (다음 장에서도 없음, web2 경로 퍼징은 순수 생성) |
| 오라클 | 상태코드로만 (정교한 오라클은 6장) |
| 피드백 | 재귀 발견 시 약하게 (아래) |
| 커버리지 | 없음 (블랙박스) |

## 준비

```bash
cd labs/web2
docker compose up --build -d
curl -s http://127.0.0.1:8080/    # 200 이면 준비 완료
```

!!! danger "실습 범위"
    대상은 본인이 방금 기동한 `127.0.0.1:8080` 컨테이너뿐입니다.
    워드리스트 퍼징은 짧은 시간에 수백~수만 건의 요청을 보냅니다.
    남의 서버에 이걸 하면 스캐닝이자 업무방해입니다. [범위와 안전](../scope-and-safety.md).

## 1. 생성이란 곧 워드리스트다

ffuf 의 핵심은 한 줄로 요약됩니다. **URL 안의 `FUZZ` 자리에
워드리스트의 각 줄을 하나씩 끼워 요청한다.**

```bash
ffuf -w wordlists/teaching.txt:FUZZ -u http://127.0.0.1:8080/FUZZ
```

- `-w 파일:키워드` — 워드리스트와, URL에서 치환할 키워드
- `-u` — `FUZZ` 를 포함한 대상 URL

이게 생성기의 전부입니다. 별도의 "지능"은 없습니다.
`teaching.txt` 에 `admin-panel` 이 있으니 `/admin-panel` 을 시도하고,
없는 `secret-vault` 는 **영원히 시도하지 않습니다.**

여기서 이 장에서 가장 중요한 문장이 나옵니다.

> 워드리스트에 없는 경로는 존재하지 않는 것과 같다.

생성기가 후보를 만들지 못하면, 오라클이 아무리 좋아도 소용없습니다.
그래서 실무에서는 [SecLists](https://github.com/danielmiessler/SecLists) 같은
큐레이션된 대형 워드리스트를 씁니다. 이 랩은 SecLists 없이도 돌아가도록
히트와 미스를 섞은 교육용 `teaching.txt`(61줄)를 함께 둡니다.

## 2. 기본 실행과 매처

인자 없이 돌리면 ffuf 는 기본 매처로 걸러 보여줍니다.

```bash
ffuf -w wordlists/teaching.txt:FUZZ -u http://127.0.0.1:8080/FUZZ -t 10
```

```text
admin-panel   [Status: 403, Size: 10,    Words: 1,  Lines: 2]
backup.zip    [Status: 200, Size: 40004, Words: 152, Lines: 149]
.env.bak      [Status: 200, Size: 44,    Words: 1,  Lines: 3]
login         [Status: 200, Size: 103,   Words: 5,  Lines: 4]
search        [Status: 200, Size: 32,    Words: 2,  Lines: 2]
user          [Status: 200, Size: 59,    Words: 10, Lines: 2]
```

- `-t 10` — 동시 요청 수(스레드). 랩이니 10으로 점잖게 둡니다.
  실무에서는 대상 서버의 부하와 계약된 요청률에 맞춰야 합니다.

주목할 점: `/admin-panel` 이 **403**인데도 잡혔습니다.
ffuf 의 기본 매처가 200만이 아니라 여러 "흥미로운" 코드
(200·204·301·302·307·401·403·405·500)를 포함하기 때문입니다.
403은 "여기 뭔가 있는데 넌 못 본다"는 강한 누설입니다. 놓치면 안 됩니다.

## 3. 매처 vs 필터

ffuf 의 판정은 두 방향입니다. 이걸 헷갈리면 결과를 통째로 오해합니다.

| | 뜻 | 예 |
|--|----|----|
| **매처** `-mc -ms -mw -ml -mt` | 조건에 맞는 것만 **남긴다** | `-mc 200,403` |
| **필터** `-fc -fs -fw -fl -ft` | 조건에 맞는 것을 **버린다** | `-fc 404` |

같은 결과를 두 방향에서 얻을 수 있습니다.

```bash
# 방법 A: 404를 버린다
ffuf -w wordlists/teaching.txt:FUZZ -u http://127.0.0.1:8080/FUZZ -mc all -fc 404 -t 10
```

`-mc all` 은 "일단 모든 코드를 매치"한 뒤, `-fc 404` 로 404만 걷어냅니다.
미존재 응답이 404 하나로 통일된 타겟에서는 이 조합이 가장 깔끔합니다.
soft-404 처럼 미존재가 200으로 오는 경우엔 코드 필터가 안 통하고,
6장의 크기·시간 필터로 넘어가야 합니다.

!!! tip "어느 쪽을 쓰나"
    **아는 신호가 있으면 매처, 아는 잡음이 있으면 필터.**
    "403·200만 궁금해" → 매처. "404는 다 쓰레기야" → 필터.
    미존재 응답이 어떻게 생겼는지 먼저 한 번 `curl` 로 확인하고 정하십시오.

## 4. 축이 둘일 때: 파일명 × 확장자

경로는 한 축이 아닙니다. 백업 파일을 찾을 땐 이름(`backup`, `db`, `config`)과
확장자(`zip`, `bak`, `sql`)를 **곱해야** 합니다. ffuf 는 워드리스트를
여러 개 걸고 각각 다른 키워드로 치환합니다 (clusterbomb 모드).

```bash
printf 'backup\nconfig\ndb\nindex\nnightly\n' > names.txt
printf 'zip\nbak\nsql\ntar.gz\n'             > ext.txt

ffuf -w names.txt:NAME -w ext.txt:EXT \
     -u "http://127.0.0.1:8080/NAME.EXT" -mc all -fc 404 -t 10
```

```text
[Status: 200, Size: 40004] * NAME: backup * EXT: zip
```

5 × 4 = 20개 조합을 던져 `backup.zip` 하나를 건졌습니다.
축이 둘이면 후보 수는 곱으로 늘어납니다. 이름 100개 × 확장자 10개 = 1000요청.
**여기서부터 요청률과 예의가 실질 문제가 됩니다** — 7장에서 다룹니다.

## 5. 재귀 — 피드백의 첫 맛

지금까지 생성기는 결과를 보지 않았습니다. 워드리스트를 처음부터 끝까지
쏟아부을 뿐입니다. 재귀 모드는 여기에 가느다란 피드백을 넣습니다.
**디렉토리가 하나 발견되면 그 아래에서 워드리스트를 다시 돌립니다.**

```bash
ffuf -w wordlists/teaching.txt:FUZZ -u http://127.0.0.1:8080/FUZZ \
     -mc all -fc 404 -recursion -recursion-depth 1 -t 10
```

이 랩의 타겟에는 파고들 하위 디렉토리를 두지 않아서 재귀가 새로
발견하는 건 없습니다. 하지만 개념은 중요합니다. 발견이 다음 탐색을
낳는 순간, 순수 생성이 **피드백 루프**로 바뀝니다. 이게 커버리지 가이드
퍼징(2장, 그리고 Part 3)의 원시적 조상입니다.

!!! danger "재귀 × soft-404 = 폭발"
    soft-404 타겟에서 재귀를 켜면 재앙입니다. 모든 경로가 200이니
    ffuf 는 **모든** 후보를 디렉토리로 착각하고, 그 아래에서 또 워드리스트
    전체를 돌리고, 그게 또 전부 200이라 또 파고듭니다. 요청 수가 지수로
    터집니다. 재귀를 켜기 전에 반드시 6장의 오라클로 soft-404 부터
    제거하십시오. **좋은 오라클은 생성기의 폭주를 막는 브레이크이기도 합니다.**

## 정리

- ffuf 의 생성은 워드리스트 치환이 전부다. **없는 후보는 못 찾는다.**
- 기본 매처는 403·401·500 등 흥미로운 코드를 포함한다 — 200만 보지 마라.
- 매처는 남기고, 필터는 버린다. 미존재 응답을 먼저 확인하고 고른다.
- 축이 둘 이상이면 곱으로 던진다. 요청 수가 폭발하니 요청률을 의식하라.
- 재귀는 발견을 탐색으로 되먹이는 첫 피드백이다. soft-404 위에서 켜면 폭발한다.

다음 장(6장)은 이 장이 미룬 질문에 답합니다. **던진 뒤 무엇을 보고
"찾았다"고 할 것인가.** 상태코드 하나로는 부족하다는 걸, soft-404 함정으로
직접 겪게 됩니다.

```bash
docker compose down    # 실습 종료
```
